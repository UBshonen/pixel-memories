# AI 협업 구조 — 자연어가 커밋이 되기까지

> "커밋까지 해줘" 한 줄이 실제로 GitHub 에 올라가기까지 무슨 일이 벌어지는가.
>
> 이 프로젝트는 코드 대부분을 AI 가 썼다. **그 구조를 모르면 설명할 수 없다.**
> 사람이 읽는 문서다.

---

# 배경 — 왜 이런 구조가 생겼나

## 처음에는 복사·붙여넣기였다

AI 에게 코드를 물어보면 **글로 답을 줬다.** 그걸 사람이 읽고, 골라서, 에디터에
붙여넣고, 저장하고, 직접 실행했다.

```text
사람   "로그인 폼 만들어줘"
AI     (코드 덩어리를 글로 출력)
사람   복사 → 붙여넣기 → 파일 이름 정하기 → 저장 → 실행 → 에러 → 다시 물어보기
```

이게 왜 불편했냐 하면, **AI 가 결과를 모른다**는 것이다. 에러가 났는지, 파일이
어디 있는지, 다른 파일과 이름이 겹치는지 알 수가 없다. 사람이 매번 상황을
글로 다시 설명해줘야 했다.

## 그래서 도구를 쥐어줬다

**AI 가 직접 파일을 읽고, 쓰고, 명령을 실행하게 하자**는 것이 지금 방식이다.
Claude Code 같은 것을 코딩 에이전트라고 부른다. *에이전트*는 "대신 일을 하는
자"라는 뜻이고, 여기서는 **혼자 판단해서 여러 단계를 이어서 하는 프로그램**을
가리킨다.

그런데 여기서 새 문제가 생긴다.

```text
파일을 쓸 수 있다  →  잘못 쓰면 내 코드가 날아간다
명령을 실행한다     →  잘못된 명령이 돌면 뭐든 일어난다
인터넷에 나간다     →  올리면 안 되는 게 올라갈 수 있다
```

**아래 네 개의 층은 전부 이 문제를 막으려고 생긴 것이다.** 층이 왜 있는지를
알고 보면 구조가 훨씬 단순해진다.

---

# 원리 — 네 개의 층

먼저 한 줄로. **특별한 통로는 없다.** AI 가 명령을 만들어서, 사람이 치는 것과
똑같이 실행한다. GitHub 에 몰래 들어가는 뒷문 같은 건 없다.

```text
"커밋까지 해줘"
  ↓  AI 가 명령 문장을 만든다
git add -A
git commit -F <메시지파일>
git push
  ↓  진짜 셸에서 실행된다
GitHub
```

## 먼저 — 셸이 뭔가

**셸**(shell)은 **사람이 컴퓨터에 글로 명령을 내리는 창구**다. Windows 의
PowerShell, Mac · Linux 의 bash 같은 것. 검은 창에 글자를 치는 그거다.

이름이 "껍데기"인 이유는, 운영체제의 알맹이(커널)를 감싸고 **사람과 알맹이
사이에서 통역**하기 때문이다.

```text
마우스로 폴더를 더블클릭     ─┐
                            ├─ 결국 같은 일. 방식만 다르다
셸에 cd docs 라고 친다      ─┘
```

**AI 가 하는 일은 이 창구에 글자를 치는 것뿐이다.** 사람이 할 수 있는 것만
할 수 있고, 사람이 못 하는 건 못 한다.

## 1층 — 자연어를 명령으로

여기까지가 AI 의 몫이다. "커밋까지" 라는 말을 받아서 이걸 정한다.

```text
지금 뭐가 바뀌었나          git status --short 로 확인
뭘 담을 것인가              git add -A
메시지를 뭐라고 쓸 것인가     이 프로젝트 규칙은 YYMMDD_작업내용
```

**판단이 들어가는 곳은 여기 하나뿐**이고, 나머지 세 층은 기계가 한다.

## 2층 — 샌드박스

### 개념

**샌드박스**(sandbox)는 직역하면 *모래놀이통*이다. 아이를 마당 전체에 풀어놓는
대신 모래통 안에서만 놀게 하면, 실컷 놀아도 집이 안 더러워진다.

프로그램에도 같은 걸 씌운다. **프로그램을 울타리 안에서만 돌게 하고, 울타리
밖은 못 건드리게 하는 것.**

```text
울타리 안    이 프로젝트 폴더 · 임시 폴더
울타리 밖    다른 폴더 · 시스템 설정 · 인터넷
```

처음 보는 개념 같지만 이미 매일 쓰고 있다. 브라우저 탭 하나하나가 샌드박스라
어떤 사이트가 다른 탭의 내용을 못 읽고, 스마트폰 앱도 각자 샌드박스 안에 있어서
앱끼리 서로의 데이터를 못 본다.

### 여기서는

**기본값이 네트워크 차단**이다. 읽기 · 쓰기 · 빌드 같은 건 되지만, **바깥으로
나가는 일은 한 번 걸린다.**

```text
2026-08-25 실제로 겪은 것

  git push
  → fatal: unable to access '...': Could not resolve host: github.com
  → 샌드박스를 끄고 다시 실행해서 성공
```

`Could not resolve host` 는 "github.com 이 어느 컴퓨터인지 알아낼 수 없다"는
뜻이다. 주소를 찾는 것부터 막히니까 인터넷이 아예 없는 것처럼 보인다.

인터넷이 고장난 게 아니라 **울타리에 걸린 것**이다. 실수로 뭔가 올라가는 사고를
줄이는 장치다.

## 3층 — 승인

AI 가 도구를 쓸 때마다 **"이거 해도 됩니까"** 하고 묻는 단계가 있다. 어떤 것을
자동으로 허용할지는 설정에 달렸다. 파일 읽기처럼 안전한 건 자동으로 두고,
지우거나 올리는 건 물어보게 하는 식이다.

그래서 **"커밋해줘" 라고 말하지 않으면 커밋은 일어나지 않는다.** AI 가 알아서
정리하고 올려두는 구조가 아니다.

## 4층 — 인증

여기가 제일 자주 오해받는 부분이다. **AI 는 GitHub 비밀번호도 토큰도 모른다.**

### 토큰이 뭔가

**토큰**(token)은 **비밀번호 대신 쓰는 열쇠**다. 호텔 카드키를 생각하면 된다.

```text
비밀번호   하나뿐이고 전부 열린다. 새면 계정 자체가 넘어간다
토큰       여러 개 만들 수 있다
           "이 저장소만" 처럼 권한을 좁힐 수 있다
           의심되면 그것만 폐기하면 된다. 비밀번호는 그대로
```

`git push` 할 때 GitHub 가 요구하는 게 이 토큰이다.

### 자격증명 관리자가 뭔가

**자격증명**(credential)은 신분을 증명하는 것 — 비밀번호나 토큰. 이걸 운영체제가
**금고에 넣어 대신 보관**해주는 기능이 자격증명 관리자다. Windows 에서는
Windows Credential Manager 라고 부른다.

핵심은 **프로그램이 금고를 열어볼 수 없다**는 것이다. 프로그램은 "github.com 에
쓸 열쇠 좀" 하고 요청하고, 금고는 **결과만** 돌려준다.

```text
git push 를 실행한다
  → Git 이 자격증명 관리자에게 요청한다
  → 금고가 저장돼 있던 토큰으로 인증을 처리한다
  → AI 는 그 값을 보지 못한다
```

**노트북에 이미 로그인돼 있기 때문에** 되는 것이다. 로그인이 안 된 컴퓨터라면
push 는 그냥 실패하고, AI 가 대신 로그인해 줄 수 없다.

## push 다음은 사람 손을 떠난다

```text
git push
  → GitHub 의 main 이 바뀐다
  → Cloudflare 가 웹훅으로 통보받는다
  → 자동으로 빌드하고 배포한다
```

### 웹훅이 뭔가

**웹훅**(webhook)은 **"일이 생기면 네가 나한테 알려줘"** 하고 미리 전화번호를
남겨두는 방식이다.

반대 방식이 **폴링**(polling) — "새 거 있어?" 를 계속 물어보는 것이다.

```text
폴링    Cloudflare 가 1분마다 GitHub 에 "바뀐 거 있어?" 라고 묻는다
        대부분 "없다". 헛물이 99%
웹훅    GitHub 가 바뀌는 순간 Cloudflare 에 "바뀌었다" 고 알린다
        낭비가 없고 즉시 반응한다
```

배달 앱이 도착할 때 알림을 보내는 것과, 내가 1분마다 앱을 여는 것의 차이다.

**그래서 push 시점이 곧 배포 시점이다.** 절차는 [../DEPLOY.md](../DEPLOY.md).

# 실무 — 이 프로젝트에서

## 실제로 이렇게 돈다

```text
사람    "표지판 빼고 커밋까지"
AI      코드 수정 → npx tsc --noEmit → npm run lint → npm run build
        git status → git add -A → git commit -F ... → git push
사람    폰에서 화면 확인
```

**검사까지가 AI 몫, 화면 확인은 사람 몫**으로 나눠 뒀다. AI 는 화면을 볼 수
없으니 "글자가 깨져 보인다" 같은 건 판단할 수 없다.

```text
npx tsc --noEmit   타입 검사만 한다. 파일은 안 만든다 (--noEmit)
npm run lint       문법은 맞지만 문제 될 코드를 잡는다
npm run build      실제로 빌드해본다. 여기까지 통과해야 push
```

## 걸리는 지점 셋

```text
네트워크 명령       샌드박스에 한 번 걸린다. 정상이다
로그인 안 된 PC     push 가 실패한다. 사람이 먼저 로그인해야 한다
"커밋" 이라고 안 하면  커밋은 안 된다. 알아서 저장해두지 않는다
```

## 이 구조에서 사람이 하는 일

AI 가 코드를 쓴다고 사람이 없어지는 게 아니라 **자리가 바뀐다.**

```text
AI 가 하는 것     타이핑 · 문법 · API 사용법 · 반복 작업 · 문서 초안
사람이 하는 것     무엇을 만들지 · 무엇을 안 만들지 · 됐는지 확인
```

이 프로젝트에서 실제로 사람이 결정한 것들 — 3배 확대, 4방향, 방향 버튼 삭제,
표지판 대신 고양이, 어르신 기준, 라이선스 선확인, Vercel 접고 Cloudflare.
**전부 AI 가 정하지 않았다.**

그리고 **검증은 사람 몫이다.** AI 가 틀린 코드를 자신 있게 쓰는 경우가 실제로
있었다. Phaser 3 문법을 4 인 줄 알고 쓴 것, 이미 고쳐진 문제의 오래된 에러 로그를
보고 엉뚱한 진단을 한 것. 그래서 **검증할 수 있는 것만 믿는다**는 원칙을 뒀다.

> **이렇게 설명하면 된다**
> "AI 에이전트가 셸을 직접 쓰는 방식이라, 자연어 지시가 git 명령으로 바뀌어
> 실행됩니다. 실행 환경은 샌드박스라 기본이 네트워크 차단이고, 인증은 로컬
> 자격증명 관리자가 처리해서 에이전트는 토큰을 보지 않습니다.
> push 하면 GitHub 웹훅으로 Cloudflare 가 빌드를 시작하니 push 시점이 곧
> 릴리스 시점이고요.
> 코드 생산은 위임했지만 무엇을 만들지와 검증 기준은 제가 정했습니다.
> 타입 검사 · 린트 · 빌드 통과까지를 에이전트 책임으로 두고, 화면 확인은
> 제가 했습니다."
