# AI 협업 구조 — 자연어가 커밋이 되기까지

> "커밋까지 해줘" 한 줄이 실제로 GitHub 에 올라가기까지 무슨 일이 벌어지는가.
>
> 이 프로젝트는 코드 대부분을 AI 가 썼다. **그 구조를 모르면 설명할 수 없다.**
> 사람이 읽는 문서다.

---

# 한 줄로

**특별한 통로는 없다.** AI 가 셸 명령을 만들어서, 사람이 치는 것과 똑같이 실행한다.

```text
"커밋까지 해줘"
  ↓  AI 가 명령을 만든다
git add -A
git commit -F <메시지파일>
git push
  ↓  진짜 셸에서 실행된다
GitHub
```

GitHub API 를 따로 부르는 것도 아니고, AI 가 계정에 로그인하는 것도 아니다.
**내 노트북의 셸을 대신 두드리는 것뿐이다.**

---

# 층이 넷 있다

## 1층 — 자연어를 명령으로

AI 가 하는 일은 여기까지다. "커밋까지" 라는 말을 받아서

```text
지금 뭐가 바뀌었나          git status --short
뭘 담을 것인가              git add -A
메시지를 뭐라고 쓸 것인가     이 프로젝트 규칙은 YYMMDD_작업내용
```

를 정하고 명령 문자열을 만든다. **판단이 들어가는 곳은 여기 하나뿐**이고,
나머지 세 층은 기계가 한다.

## 2층 — 실행 환경 (샌드박스)

명령은 격리된 환경에서 돈다. 기본값이 **네트워크 차단**이다.

```text
2026-08-25 실제로 겪은 것

  git push
  → fatal: Could not resolve host: github.com
  → 샌드박스를 끄고 다시 실행해서 성공
```

읽기·쓰기·빌드 같은 건 샌드박스 안에서 되지만, **바깥으로 나가는 일은
한 번 걸린다.** 실수로 뭔가 올라가는 사고를 줄이는 장치다.

## 3층 — 승인

도구 호출마다 승인 단계가 있다. 어떤 명령을 자동으로 허용할지는 설정에 달렸다.
사용자가 거부하면 그 명령은 실행되지 않는다.

그래서 **"커밋해줘" 라고 말하지 않으면 커밋은 일어나지 않는다.** AI 가 알아서
정리하고 올려두는 구조가 아니다.

## 4층 — 인증

여기가 제일 자주 오해받는 부분이다.

**AI 는 GitHub 비밀번호도 토큰도 모른다.**

```text
git push 를 실행한다
  → Git 이 자격증명 관리자(Windows Credential Manager)에게 묻는다
  → 거기 이미 저장돼 있던 토큰으로 인증한다
  → AI 는 그 값을 보지 못한다
```

노트북에 **이미 로그인돼 있기 때문에** 되는 것이다. 로그인이 안 된 컴퓨터라면
push 는 그냥 실패한다. AI 가 대신 로그인해 줄 수 없다.

---

# push 다음은 사람 손을 떠난다

```text
git push
  → GitHub 의 main 이 바뀐다
  → Cloudflare 가 웹훅으로 통보받는다
  → 자동으로 빌드하고 배포한다
```

**그래서 push 시점이 곧 배포 시점이다.** 절차는 [../DEPLOY.md](../DEPLOY.md).

---

# 이 구조에서 사람이 하는 일

AI 가 코드를 쓴다고 해서 사람이 없어지는 게 아니라, **자리가 바뀐다.**

```text
AI 가 하는 것        타이핑 · 문법 · API 사용법 · 반복 작업 · 문서 초안
사람이 하는 것        무엇을 만들지 · 무엇을 안 만들지 · 됐는지 확인
```

이 프로젝트에서 실제로 사람이 결정한 것들 —
3배 확대, 4방향, 방향 버튼 삭제, 표지판 대신 고양이, 어르신 기준,
라이선스 선확인, Vercel 접고 Cloudflare. 전부 AI 가 정하지 않았다.

그리고 **검증은 사람 몫이다.** AI 가 틀린 코드를 자신 있게 쓰는 경우가 실제로
있었다(Phaser 3 문법, 오래된 에러 로그). 그래서 이 프로젝트는
`tsc --noEmit` · `lint` · `build` 를 통과시키는 것까지를 AI 의 책임으로 두고,
화면 확인은 사람이 한다.

> **이렇게 설명하면 된다**
> "AI 에이전트가 셸을 직접 쓰는 방식이라, 자연어 지시가 git 명령으로 바뀌어
> 실행됩니다. 인증은 로컬 자격증명 관리자가 하고 에이전트는 토큰을 보지 않습니다.
> 실행 환경은 기본이 네트워크 차단이라 외부로 나가는 명령은 한 번 더 승인을
> 거칩니다. push 가 배포 트리거라 릴리스 시점이 곧 push 시점이고요.
> 코드 생산은 위임했지만 무엇을 만들지와 검증 기준은 제가 정했습니다."
